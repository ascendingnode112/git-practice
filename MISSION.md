# Mission: Git Fundamentals

## Why
Chris wants to stop running Git commands from memory or copy-paste and actually understand what Git is doing underneath, so day-to-day version control feels confident and mistakes stop being scary — they become recoverable.

## Success looks like
- Can predict what `git status`, `git add`, `git commit`, and `git merge` will do *before* running them
- Can create, switch, and merge branches without anxiety, including resolving a simple conflict
- Can recover from common mistakes (committed on the wrong branch, bad commit message, want to undo a change) without searching the web
- Can read `git log` and explain what the history of a repo means
- Can explain how GitHub relates to Git — remotes, push/pull/fetch, and what a pull request actually is — and move work between this machine and GitHub without guessing

## Constraints
- Beginner starting point: can commit and push by following steps, but the underlying model is fuzzy
- Prefers short, hands-on lessons practiced live in this repo (`~/git-practice`)
- Technical background (Director of Engineering) — no need to explain what a terminal is; skip the basics of *computing*, not of *Git*

## Out of scope
- Interactive rebase and history rewriting (until fundamentals are solid)
- Git internals / plumbing commands
- Team PR / code-review *workflow conventions* (branching strategies, review etiquette — a possible later mission; the PR mechanism itself is in scope)
