The Git Mental Model

Reference · git-practice

The one-sentence model

Git is a series of snapshots of your whole project. A commit is one snapshot, plus a pointer to the snapshot that came before it.

Source: Pro Git §1.3, "Snapshots, Not Differences"

The three areas

Working directorythe files you edit
git add →
Staging areathe next snapshot, assembled
git commit →
Repositorypermanent snapshots (.git)

Every file change flows left to right. git status tells you where each change currently sits.

Core commands

CommandWhat it actually does
git statusShows where every change sits across the three areas. Safe, run it constantly.
git add <file>Copies the file's current state into the staging area. Editing after add requires another add.
git commit -m "…"Turns the staging area into a permanent snapshot in the repository.
git log --onelineLists snapshots, newest first: short hash + message.
git diffWorking directory vs. staging area — what you have NOT staged yet.
git diff --stagedStaging area vs. last commit — exactly what the next commit will contain.

Facts that prevent confusion later

FactWhy it matters
A commit is a snapshot, not a diff.Git shows you diffs, but it stores full snapshots. Checking out any commit restores everything instantly.
Staging is a copy, not a mark.git add copies content at that moment. Later edits are not included until you add again.
Committed work is nearly impossible to lose.Once snapshotted, Git keeps it even through most mistakes. Danger only lives in never-committed changes.
The hash identifies the snapshot.Every commit's ID (e.g. 5738bc2) is a checksum of its content — same content, same ID, tamper-evident.
