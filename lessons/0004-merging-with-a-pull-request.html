Two new ideas

1. A pull request tracks a branch, not a batch of commits

Your open PR is titled "Add a note to the README" — because when it was created, that was the branch's story. But a PR is a live proposal: merge branch X into branch Y. Every commit you've pushed to add-notes since has flowed into it automatically. It now carries your entire teaching workspace, and today's housekeeping commit will join it too, seconds after you push. (GitHub Docs, "About pull requests")

2. Merging moves the target pointer — via a merge commit

When you press the merge button, GitHub creates a merge commit — a snapshot with two parents (old main and the tip of add-notes) — and moves remote main to it. That's the whole event. add-notes doesn't move; nothing on your machine moves. Your local main and your origin/main record only catch up when you fetch — and until then, git status will happily report "up to date," because it only ever compares against your stale local record, never the network. (Pro Git §3.2)

The drill

Predict every output before reading it. On the merge screen, use the default "Merge pull request" button — not Squash or Rebase (those rewrite history; later topic, if ever). 

# 1. Housekeeping reps: snapshot last night's learning records, send up.
git status          # predict: GLOSSARY, NOTES, two records modified; record 0005 + this lesson untracked
git add .
git commit -m "Record lesson 3 results and add lesson 4"
git push

# 2. Watch the open PR grow. Its title is stale; its contents are live.
gh pr view          # predict: title "Add a note to the README" — but look at the commit list
gh pr view --web    # browse the Commits and Files-changed tabs: your whole workspace is in there

# 3. Merge it: green "Merge pull request" button → Confirm.
#    Afterward GitHub offers "Delete branch" — click it. It deletes only the
#    remote LABEL; every commit is now reachable from main. (Labels, not containers.)

# 4. Back in the terminal: your machine has not heard the news.
git switch main
git status          # predict: "up to date with 'origin/main'" — true vs your STALE record, false vs GitHub
git fetch
git status          # predict: "behind 'origin/main' by 6 commits, can be fast-forwarded"
git pull            # predict: Fast-forward — local main slides up to the merge commit
git log --oneline --graph   # find the diamond: one commit with two parent lines

# 5. Cleanup: the label did its job.
git branch -d add-notes     # predict: deletes cleanly — nothing is stranded
git fetch --prune           # drop the remote-tracking record for the deleted remote branch
git branch -a -v            # predict: main + origin/main, together at the merge commit

From here on, you work on main — the branch cycle (branch → commits → PR → merge → delete) is complete, and it's the same loop your engineers run every day.
