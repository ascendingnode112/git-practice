The GitHub Model

Reference · git-practice

The one-sentence model

Git is the tool; GitHub is a hosting service that keeps a copy of your repository (a remote) and wraps a collaboration layer — pull requests, issues, forks — around it.

Source: GitHub Docs, "About remote repositories"

Local ↔ remote

Local repositorythis machine — full history, works offline
push →
← fetch / pull
Remote "origin"github.com — a full copy, not the "master" copy

Both sides hold the complete snapshot chain. Neither is inherently primary — origin is just the conventional nickname for the remote you cloned from or added first.

Remote commands

CommandWhat it actually does
git remote -vLists your remotes and their URLs. Safe, run any time.
git pushUploads local commits the remote doesn't have, on the current branch.
git fetchDownloads new remote commits but touches none of your files. Always safe.
git pullfetch + merge into your current branch. Changes your files.
git clone <url>Copies an entire remote repository — full history — and wires up origin.
git push -u origin <branch>First push of a new branch; -u links it to the remote branch so plain push/pull work after.

The collaboration layer (GitHub, not Git)

ConceptWhat it is
Pull request (PR)A request to merge one branch into another, with a place for review and discussion attached. Lives on GitHub, not in Git itself.
ForkYour own server-side copy of someone else's repository — lets you push freely, then PR back.
IssueA tracked discussion thread (bug, task, question) attached to the repository.
Tracking branchThe pairing shown as add-notes...origin/add-notes in git status — how Git knows where plain push/pull should go.

Facts that prevent confusion later

FactWhy it matters
Git works fully without GitHub.Commits, branches, history — all local. Only push/fetch/pull touch the network.
Push sends commits, not files.Uncommitted edits never reach GitHub, no matter how many times you push.
"Pull request" is really a merge request.The name reads backwards: you're asking the target branch to pull your branch in.
fetch is always safe; pull can merge.When unsure what's on the remote, fetch first and look — nothing local changes.
